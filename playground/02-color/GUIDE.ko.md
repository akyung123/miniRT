## 0. 왜 이걸 하는가

내가 최종적으로 구현할 함수의 반환 규약이 이겁니다:

```c
t_color render_pixel(t_scene *scene, int x, int y);
/* t_color = t_vec3, x/y/z가 각각 r/g/b, 범위는 0.0 ~ 1.0 */
```

즉 **렌더러 안에서는 색이 항상 실수 0~1**이고, 정수 0~255로 바꾸는 건 출력 쪽(`color_to_int`)이 이미 해줍니다. 이 경계를 지금 몸에 익혀두지 않으면 5단계 조명에서 "왜 다 하얗지" 또는 "왜 다 까맣지"로 하루를 날립니다.

**왜 실수로 다루나?** 조명 계산은 곱셈의 연속입니다. `0.2 × 0.7 = 0.14`처럼 곱해도 범위가 유지되는 게 0~1이라서요. 정수 0~255로 곱하면 매번 나눠줘야 하고 반올림 오차가 쌓입니다.

---

## 1. 배울 개념

### (1) 두 세계의 색

| | 범위 | 쓰는 곳 |
|---|---|---|
| 정규화 색 | `0.0 ~ 1.0` (double) | 렌더러 내부 계산 전부 |
| 정수 색 | `0 ~ 255` (int) | 화면에 쓸 때, .rt 파일 |

파서는 `.rt`의 `255,0,0`을 읽어서 **이미 `/255.0` 해서 0~1로 넣어줍니다** (`parse_color`). 그러니 씬에서 온 색은 손댈 필요 없습니다.

### (2) 패킹

```c
color = (r << 16) | (g << 8) | b;   /* r,g,b 각각 0~255 */
```

한 픽셀 = 32비트 = `0x00RRGGBB`. 위쪽 8비트는 안 씁니다.

### (3) 선형 보간 (lerp)

```
lerp(a, b, t) = (1 - t) * a + t * b        t: 0.0 ~ 1.0
```

`t=0`이면 a, `t=1`이면 b, 중간이면 섞임. 3단계 하늘 배경, 5단계 조명 혼합에 그대로 나옵니다. **벡터에도 그대로 적용됩니다** (성분별로).

### (4) 클램프

계산 결과가 0~1을 벗어날 수 있습니다. 조명을 여러 개 더하면 1을 넘고, 뺄셈이 섞이면 음수가 나옵니다. **정수로 바꾸기 직전에 반드시 잘라야** 합니다. 안 하면 `1.4 × 255 = 357`이 int로 잘리면서 엉뚱한 색으로 튑니다 (빨강이 넘치면 초록 채널을 침범).

### (5) 색끼리의 곱 vs 합

- **곱(성분별)** = 필터. 빨간 물체 × 파란 빛 = 검정. 물체 색과 빛 색을 합칠 때
- **합** = 광원 추가. 여러 조명의 기여를 더할 때

5단계에서 `물체색 × 광원색 × 밝기` 형태로 쓰게 됩니다.

## 3. 함정

**정수 나눗셈.** `x / WIN_WIDTH`는 C에서 `int / int`라 항상 0입니다. `(double)x / WIN_WIDTH` 또는 `x / (double)WIN_WIDTH`.

**255냐 256이냐.** `(int)(c * 255.0)`이면 `c=1.0`일 때 정확히 255. `* 256`을 쓰면 256이 나와 오버플로합니다. **255를 쓰세요.**

**클램프를 곱하기 전에 하기.** 순서는 반드시 **클램프 → 곱하기 → 캐스팅**입니다.

**`(int)` 캐스팅은 내림입니다.** 반올림이 아닙니다. 이 단계에선 신경 안 써도 되지만 알고는 있을 것.

**음수 클램프를 빠뜨리기.** 5단계에서 `dot`이 음수가 나오는 순간 바로 터집니다. 지금 넣어두세요.
