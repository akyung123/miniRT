## 0. 왜 재미있나

지금까지는 정지 이미지였습니다. 카메라를 움직여보면 **내가 만든 3D 공간이 진짜 3D라는 게 체감**됩니다. 그리고 디버깅 도구로도 훌륭합니다 — 원기둥 뒤로 돌아가서 캡을 확인하는 게 씬 파일 고치는 것보다 훨씬 빠릅니다.

---

## 1. 개념

### 이벤트 → 상태 변경 → 재렌더

```
키 입력  →  카메라 위치/방향 갱신  →  render_all 다시  →  put_image
```

0단계에서 등록한 `mlx_key_hook`을 그대로 씁니다. 콜백 안에서 카메라를 바꾸고 렌더 함수를 다시 부르면 끝입니다.

### 이동 방향은 카메라 기준

월드 축이 아니라 **카메라의 축**으로 움직여야 자연스럽습니다. 9단계에서 만든 `forward` / `right` / `up`을 그대로 씁니다.

```
W/S  →  position ± forward * speed
A/D  →  position ± right   * speed
Q/E  →  position ± up      * speed
```

### 회전

`orientation` 벡터를 돌립니다. 축 기준 회전은 로드리게스 공식이나 회전행렬을 쓰는데, 간단히는 **yaw(좌우) / pitch(상하)** 각도를 상태로 들고 있다가 매번 방향 벡터를 다시 만드는 편이 쉽습니다.

```
forward.x = cos(pitch) * sin(yaw)
forward.y = sin(pitch)
forward.z = cos(pitch) * cos(yaw)
```

pitch를 ±89°로 제한하세요. 90°에서 9단계의 **cross 영벡터 예외**를 정확히 밟습니다.

## 2. 성능 — 여기가 진짜 문제

800×600 전체 재렌더는 도형이 몇 개만 돼도 **눈에 띄게 느립니다.** 키를 누르고 한참 기다리는 경험이 됩니다.

해결책 (쉬운 순):

1. **저해상도 미리보기** — 움직이는 동안 200×150으로 렌더하고 픽셀을 4×4로 확대. 키를 뗀 뒤 전체 해상도로 한 번 더
2. **이미지 버퍼 재사용** — 매번 `mlx_new_image` 하지 말고 하나를 계속 덮어쓰기 (1단계에서 만든 구조 그대로)
3. **`mlx_loop_hook` 사용** — 키 입력 상태를 배열로 들고 있다가 매 프레임 처리. 키를 누르고 있는 동안 부드럽게 움직입니다

**1번만 해도 체감이 완전히 달라집니다.**

## 3. 구현 순서

- [ ] **1. 카메라 상태를 구조체로 분리** — position, yaw, pitch

- [ ] **4. 저해상도 미리보기** — 여기서 쾌적해집니다

- [ ] **6. (선택) `mlx_loop_hook` + 키 상태 배열** — 부드러운 연속 이동

## 4. 함정

**키 훅 안에서 렌더가 오래 걸리면 입력이 밀립니다.** 키를 여러 번 누르면 큐에 쌓여서 손을 뗀 뒤에도 계속 움직입니다. 저해상도 미리보기가 이걸 완화합니다.

**pitch가 ±90°에 도달** → cross 영벡터 → 화면이 검게. 9단계에서 예외 처리를 해뒀어도 제한하는 게 낫습니다.

**매 프레임 `mlx_new_image`** → 메모리가 계속 쌓입니다. 이미지 하나를 재사용하세요.

**mandatory 코드를 건드리기** → 이 브랜치는 실험용입니다. `feature/render-pixel`에는 **아무것도 반영하지 마세요.** 보너스는 별도 파일(`_bonus.c`)로 관리하는 게 42 규칙입니다.
