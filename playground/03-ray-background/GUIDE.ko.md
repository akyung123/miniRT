---

## 0. 왜 이걸 하는가

레이트레이싱의 전체 구조가 이 한 줄입니다:

```
픽셀 (x,y) → 광선 하나 → 그 광선이 만난 것의 색
```

앞으로 나올 구·평면·원기둥은 전부 "**이 광선이 그 도형과 만나는가**"를 푸는 문제일 뿐입니다. 이 단계에서는 **아직 도형이 없고**, 광선 방향만으로 하늘색을 칠합니다. 도형이 없는데도 그림이 나오는 게 요점입니다 — 좌표 매핑이 맞는지 검증하는 게 목적이거든요.

---

## 1. 배울 개념

### (1) 광선 = 시작점 + 방향

```c
typedef struct s_ray
{
    t_vec3  origin;      /* A: 어디서 출발하는가 (카메라) */
    t_vec3  direction;   /* b: 어느 쪽으로 가는가 (단위벡터) */
}   t_ray;
```

```
P(t) = A + t * b
```

`t`를 키우면 광선을 따라 앞으로 나아갑니다. **b가 단위벡터일 때만 `t`가 곧 거리**입니다. 이게 6단계 그림자에서 "광원까지의 거리 안에 물체가 있나"를 판정할 때 결정적입니다. 지금부터 방향은 항상 정규화하세요.

### (2) 화면 좌표 → 뷰포트 좌표

픽셀은 `x: 0~799`, `y: 0~599`인 정수입니다. 이걸 3D 공간의 실수 좌표로 옮겨야 합니다.

```
u = x / (WIDTH  - 1)        →  0.0 ~ 1.0
v = y / (HEIGHT - 1)        →  0.0 ~ 1.0
```

그다음 화면 중앙이 0이 되도록 옮기고, **y축을 뒤집습니다.**

```
screen_x = (2*u - 1) * aspect        /* -aspect ~ +aspect */
screen_y = (1 - 2*v)                 /* +1 (위) ~ -1 (아래) */
```

### (3) y축 뒤집기 — 이 단계에서 제일 많이 틀리는 곳

**화면은 y가 아래로 증가하고, 3D 공간은 y가 위로 증가합니다.** 뒤집기를 빼먹으면 그림이 위아래로 뒤집혀 나옵니다. 그런데 배경 그라디언트만 있을 땐 "그냥 색이 반대네" 정도로 보여서 놓치기 쉽고, 4단계에서 구를 놓고 나서야 알게 됩니다.

### (4) 종횡비 (aspect ratio)

```
aspect = WIDTH / (double)HEIGHT      /* 800/600 = 1.333 */
```

가로가 세로보다 1.33배 넓으니 x 범위도 그만큼 넓어야 합니다. 안 하면 **원이 타원으로 찌그러집니다.** 지금은 안 보이고 4단계에서 드러납니다.

### (5) 이 단계의 임시 카메라

아직 씬 파일을 안 씁니다. 하드코딩:

```
origin = (0, 0, 0)
화면은 z = -1 평면에 놓기
direction = normalize(screen_x, screen_y, -1)
```

9단계에서 이 부분만 `scene->camera`로 갈아끼우면 됩니다.

### (6) 배경색

```
t = 0.5 * (ray.direction.y + 1.0)        /* -1~1 을 0~1 로 */
color = lerp(흰색, 하늘색, t)
```

2단계에서 만든 lerp 그대로입니다.

## 2. vec3 유틸

여기서부터 벡터 연산이 필요합니다. `origin/feature/vec3-render-interface` 브랜치에 10종이 이미 있습니다:

```
vec3_add  vec3_sub  vec3_scale  vec3_negate  vec3_mul
vec3_dot  vec3_cross  vec3_length  vec3_normalize  vec3_clamp
```

**다만 가져다 쓰기 전에 직접 한 번 타이핑해보세요.** 특히 `cross`와 `normalize`는 손으로 써봐야 9단계 카메라 기저에서 안 막힙니다. 다 짜고 나서 비교하면 됩니다.

- [ ] **5. 하늘 배경** — `dir.y`로 lerp
- [ ] **6. 종횡비 넣기** — aspect 곱하기 전후를 비교

---

## 4. 함정

**정규화를 빠뜨리기.** `t`가 거리가 아니게 되고, 6단계에서 그림자가 이상해집니다. 원인 찾기가 매우 어렵습니다.

**y 뒤집기를 빠뜨리기.** 4단계에서 구가 반대편에 나타납니다.

**`WIDTH - 1`인가 `WIDTH`인가.** 둘 다 돌아갑니다. 엄밀하게는 픽셀 중심을 쓰려면 `(x + 0.5) / WIDTH`가 맞지만, 이 단계에서는 어느 쪽이든 상관없습니다. 나중에 안티에일리어싱을 넣는다면 그때 의미가 생깁니다.

**정수 나눗셈** — 2단계와 같은 함정. `(double)` 캐스팅 잊지 말 것.

**요구하는 함수**:

```c
t_vec3	vec3_add(t_vec3 a, t_vec3 b);
t_vec3	vec3_sub(t_vec3 a, t_vec3 b);
t_vec3	vec3_scale(t_vec3 v, double t);
t_vec3	vec3_cross(t_vec3 a, t_vec3 b);
double	vec3_dot(t_vec3 a, t_vec3 b);
double	vec3_length(t_vec3 v);
t_vec3	vec3_normalize(t_vec3 v);

```

`t_ray`는 `{ t_vec3 origin; t_vec3 direction; }`로 가정합니다.

**검사 19개** — 주요한 것:

| 검사 | 입력 | 기대 |
|---|---|---|
| dot | `(1,2,3)·(4,5,6)` | 32 |
| **cross 순서** | `cross(x,y)` / `cross(y,x)` | `+z` / `-z` |
| **cross 평행** | `cross((1,0,0),(2,0,0))` | 영벡터 (9단계 예외의 원인) |
| normalize | `(0,3,4)` | `(0,0.6,0.8)`, 길이 1 |
| ray_at | `A=(0,0,0)`, `b=(0,0,-1)`, `t=5` | `(0,0,-5)` |
| **정규화** | `camera_ray(400,300)` | 방향 길이 = 1 |
| 중앙 | 〃 | ≈ `(0,0,-1)` |
| 좌우 대칭 | `x=0` vs `x=799` | 부호 반대 |
| **y 뒤집기** | `y=0` / `y=599` | `dir.y > 0` / `< 0` |
| **종횡비** | 가로 끝 vs 세로 끝 | 가로가 더 넓음 |
