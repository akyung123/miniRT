# 1단계 — 이미지 버퍼와 2D 도형

0단계 이어서 쓰는 학습용 폴더. 제출 대상 아니고, 끝나면 지웁니다.

**한 줄 요약**: 픽셀을 "그려달라고 부탁하는 것"에서 **"메모리에 직접 쓰는 것"**으로 바꾼다.

---

## 0. 왜 이걸 하는가

0단계 마지막에 본 두 가지 불편을 여기서 해결합니다.

1. **점이 사라졌다** — `mlx_pixel_put`으로 찍은 픽셀은 창이 다시 그려질 때(expose) 날아갔습니다. 창은 내가 그린 걸 기억하지 않으니까요.
2. **48만 번은 무리다** — 800×600 = 480,000픽셀. 픽셀마다 함수 호출로 윈도우 시스템에 부탁하면 레이트레이서로 못 씁니다.

이미지 버퍼가 둘 다 해결합니다. **내 메모리에 그림을 들고 있으니** 다시 그려달라면 그냥 다시 올리면 되고, 전송은 프레임당 딱 한 번입니다.

**이 단계에서 만드는 `put_pixel` 하나가 앞으로 miniRT 전체에서 계속 쓰입니다.** 여기서 대충 넘어가면 4단계, 8단계에서 "왜 화면이 이상하지"로 돌아옵니다.

---

## 1. 배울 개념 4개

### (1) 이미지 = 그냥 커다란 픽셀 배열

`mlx_new_image`가 주는 건 마법 객체가 아니라 **800×600개의 픽셀이 일렬로 늘어선 메모리 덩어리**입니다. `mlx_get_data_addr`가 그 첫 주소를 알려주면, 그다음부터는 mlx와 상관없는 순수한 포인터 연산입니다.

### (2) 주소 계산 공식

```
addr + (y * size_line + x * (bpp / 8))
```

- `bpp / 8` — 픽셀 하나가 몇 바이트인가 (보통 32비트 = **4바이트**)
- `y * size_line` — y번째 줄의 시작 위치
- 이 주소를 `unsigned int *`로 캐스팅해서 색을 씁니다

### (3) `size_line`이 왜 따로 있는가 ← 여기가 핵심

"한 줄 = `width * 4`바이트" 같아 보이지만 **아닐 수 있습니다.** 시스템이 각 줄 끝에 남는 바이트(padding)를 붙여 정렬해두기도 하거든요.

그래서 `width * 4`로 직접 계산하면 줄마다 조금씩 어긋나서 **이미지가 대각선으로 비스듬히 밀려 보입니다.** 이 증상을 보면 바로 이걸 의심하세요. 반드시 `mlx_get_data_addr`이 채워준 `size_line`을 쓸 것.

### (4) 화면 좌표계

원점은 **좌상단**, y는 **아래로** 증가. 수학 시간의 좌표계와 y축이 반대입니다. 0단계에서 축을 그려봤다면 이미 아는 것.

`endian`은 맥에서는 보통 신경 안 써도 됩니다. 색이 빨강↔파랑으로 뒤집혀 보이면 그때 보세요.

---

## 2. 쓸 함수 3개

```c
void *mlx_new_image(void *mlx_ptr, int width, int height);
char *mlx_get_data_addr(void *img_ptr, int *bits_per_pixel, int *size_line, int *endian);
int   mlx_put_image_to_window(void *mlx_ptr, void *win_ptr, void *img_ptr, int x, int y);
```

**`mlx_new_image`** — 픽셀 배열 확보. 실패하면 `NULL`.

**`mlx_get_data_addr`** — 첫 주소를 반환하면서 `bpp` / `size_line` / `endian`을 **출력 인자로 채워줍니다.** 이 셋은 나중에 계속 필요하니 구조체에 보관.

**`mlx_put_image_to_window`** — 마지막 두 인자는 **창 안에서 이미지를 놓을 위치**입니다. 화면 전체를 채우려면 `0, 0`. (`WIN_WIDTH/2, WIN_HEIGHT/2`를 넣으면 이미지가 오른쪽 아래로 밀려서 1/4만 보입니다.)

## 3. 이미 있는 코드에서 손봐야 할 것

`main.c`는 0단계에서 복사해 온 상태라 이미 `init_minirt`에서 이미지 생성과 `mlx_get_data_addr`까지 해두었습니다. 여기서 바꿀 건 세 군데입니다.

- [ ] `draw()`가 아직 `mlx_pixel_put`을 씁니다 → **내 `put_pixel`로 교체**. 이번 단계 규칙은 **`mlx_pixel_put` 한 번도 안 쓰기**입니다.
- [ ] `mlx_put_image_to_window` 호출이 주석 처리되어 있습니다 → 살리고, 좌표는 `0, 0`으로.
- [ ] `mlx_loop` 뒤의 `mini_destroy`는 **절대 실행되지 않습니다** (`mlx_loop`은 리턴 안 함). 정리는 종료 훅 안에서.

## 4. 구현 순서 (하나씩, 확인하면서)

각 항목마다 창을 띄워서 눈으로 보고 다음으로 넘어가세요. 한꺼번에 짜면 어디가 틀렸는지 못 찾습니다.

- [ ] **1. `put_pixel` 작성** — `draw.c`에 위 주소 공식으로. 인자는 `(t_mlx *mlx, int x, int y, int color)`
- [ ] **2. 화면 전체 한 색으로** — 이중 루프로 전부 칠하기. 창이 통째로 그 색이면 **주소 계산이 맞은 것**. 여기가 1단계에서 제일 중요한 통과 지점입니다
- [ ] **3. 사각형** — `x1 <= x < x2 && y1 <= y < y2`
- [ ] **4. 원** — `(x-cx)² + (y-cy)² < r²`. **`sqrt` 쓰지 마세요.** 양변 제곱 상태로 비교하는 게 빠르고, 이 사고방식이 4단계 구(sphere) 교차에서 똑같이 나옵니다
- [ ] **5. 그라디언트** — `x`를 0~255로 매핑해서 좌우로. `(r << 16) | (g << 8) | b`
- [ ] **6. 성능 비교** — `cd ../../srcs/output && make perf` 로 두 방식의 시간 차이를 숫자로 확인

## 5. 함정

**범위 검사를 직접 해야 합니다.** `mlx_pixel_put`은 화면 밖 좌표를 알아서 무시해줬지만, **메모리에 직접 쓰기는 아무도 안 막아줍니다.** 원을 그리다 좌표가 음수로 가면 남의 메모리를 조용히 덮어쓰고, 증상은 한참 뒤 엉뚱한 데서 터집니다.

> Makefile에 `-fsanitize=address`가 이미 들어 있습니다. 범위를 넘으면 주소 새니타이저가 잡아주니, 이 단계에서는 그대로 두는 게 이득입니다.

**`mlx_put_image_to_window`를 안 부르면 아무것도 안 보입니다.** 메모리에는 그림이 있는데 화면에는 없는 상태. 반대로 **픽셀마다 부르면 의미가 없습니다** — 다 쓰고 **마지막에 한 번**.

**이미지가 비스듬히 밀리면** `size_line` 문제입니다 (위 1-(3)).

**주어진 케이스 파일** — `../tests/cases/01-pixels/` 안의 7개. **이 파일들이 전부 통과하면 이 단계 완료**입니다.

- `01_put_pixel.case`
- `02_size_line.case`
- `03_bounds.case`
- `04_circle.case`
- `05_circle_clipped.case`
- `06_square.case`
- `07_color.case`

케이스는 `.rt`를 닮은 텍스트 파일이라 **재컴파일 없이 직접 추가할 수 있습니다.** 도형은 `.rt`와 똑같이 지름으로 적습니다. 문법과 명령 목록은 `../tests/SPEC.ko.md`.

**요구하는 함수**:

```c
void	my_mlx_pixel_put(t_mlx *mlx, int x, int y, int color);
void	draw_circle(t_mlx *mlx, int cx, int cy, int r, int color);
void	draw_square(t_mlx *mlx, int x1, int x2, int y1, int y2, int color);
int		create_argb(int a, int r, int g, int b);
```

**검사 28개** — 주요한 것:

| 검사 | 입력 | 잡는 실수 |
|---|---|---|
| **패딩** | `size_line = W*4 + 64` | **`width*4` 하드코딩** |
| 범위 | `(-1,300)` `(800,300)` `(400,-1)` `(400,600)` `(-5000,-5000)` | 경계 검사 누락 |
| 원 속참 | 중심·중간·경계 안쪽 | 테두리만 그려짐 |
| 원 경계 | `(502,300)` `(471,371)` | 부등호 실수 |
| 잘린 원 | 중심 `(0,0)` r=50 | 버퍼 넘침 |
| 사각형 | `(10,40,60,100)` | off-by-one (정확히 1200픽셀) |
| 색 | `create_argb(0,255,255,255)` | 알파 255 → 투명 |

`draw_square`는 **반열린 구간**(`x2`, `y2` 제외)으로 검사합니다.
