## 0. 왜 이걸 하는가

두 가지입니다.

1. **평면은 세 도형 중 가장 쉽습니다.** t에 대해 **1차**라서 판별식도 근 선택도 없습니다. 구 다음에 하기 딱 좋습니다.
2. **도형이 2종이 되는 순간 구조가 필요해집니다.** 지금까지는 구만 있어서 대충 넘어갔지만, 이제 "여러 도형을 돌면서 최소 t를 찾는" 코드가 있어야 합니다. **이 구조가 8단계 원기둥을 그냥 추가만 하면 되게 만들어줍니다.**

그리고 이 단계 끝에 **구가 바닥에 그림자를 드리우는 그림**이 나옵니다. 3~7단계가 전부 맞았다는 증거이고, 심리적으로 제일 큰 분기점입니다.

## 1. 수식

### 평면의 정의

점 `P0`를 지나고 법선이 `n`인 평면 위의 점 `P`는:

```
dot(n, P - P0) = 0
```

"평면 위의 어떤 방향이든 법선과 수직"이라는 뜻입니다.

### 대입

`P = A + tb`:

```
dot(n, A + tb - P0) = 0
dot(n, A - P0) + t · dot(n, b) = 0
```

```
t = dot(n, P0 - A) / dot(n, b)
```

**t에 대해 1차**입니다. 근이 하나뿐이라 고를 것도 없습니다.

### 분모가 0이면

```
dot(n, b) ≈ 0    →    광선이 평면과 평행    →    교차 없음
```

`== 0`으로 비교하지 마세요. `fabs(denom) < 1e-6`.

### 법선

평면의 법선은 **모든 점에서 동일**합니다. 그냥 `n`. 다만 광선을 등지고 있으면 뒤집어야 합니다 (5단계와 같음).

## 2. 도형 리스트 구조

이제 도형이 2종이니 정리할 때입니다.

```
t_hit  hit_scene(scene, ray, t_min, t_max)
{
    가장 가까운 것 = 없음
    closest = t_max
    for (도형 in 리스트)
    {
        if (그 도형과 교차 && t < closest)
        {
            closest = t
            가장 가까운 것 = 그 교차 정보 (t, 점, 법선, 색)
        }
    }
    return 가장 가까운 것
}
```

핵심은 **`closest`를 계속 좁혀가는 것**입니다. 이러면 자연스럽게 가려짐(occlusion)이 처리됩니다.

`t_hit`에 담을 것: `t`, 교차점 `P`, 법선 `n`, 색. **도형 종류는 안 담아도 됩니다** — 교차 시점에 필요한 정보를 다 뽑아뒀으니까요. 이 분리가 8단계에서 원기둥을 넣을 때 조명 코드를 한 줄도 안 건드리게 해줍니다.

씬의 도형은 연결 리스트(`t_object *objects`, `next` 포인터)로 옵니다. `type`으로 분기해서 각 교차 함수를 부르면 됩니다.

## 4. 함정

**분모를 `== 0`으로 비교** → 부동소수점에서는 거의 절대 정확히 0이 아닙니다. `fabs(denom) < 1e-6`.

**평면은 무한합니다.** 화면 절반이 통째로 평면 색으로 덮이는 게 정상입니다. "너무 크게 나오는데?"가 아닙니다.

**평면이 카메라 뒤에서도 보인다** → `t > t_min` 검사 누락. 평면은 무한해서 이 실수가 화면 전체를 덮어버립니다. 증상이 극적이라 오히려 찾기 쉽습니다.

**법선 뒤집기를 평면에도 적용해야 합니다.** 평면을 아래에서 올려다보면 법선이 반대를 향합니다.

**그림자 판정에서 평면을 빼먹기** → 바닥이 구를 가리는 경우가 처리 안 됩니다. `hit_scene`으로 통일했으면 자동으로 해결됩니다.
