# 학습 계단 0 → 10

`render_pixel` 하나를 스스로 짜기 위한 연습 경로. 여기 있는 건 전부 **학습용이고 제출 대상이 아닙니다.** 끝나면 통째로 지우고, 정리된 코드만 `feature/render-pixel` 브랜치로 옮깁니다.

## 규칙

- **한 폴더 = 한 단계 = 한 브랜치.** 앞 단계 브랜치에서 파생시킬 것 (매번 main에서 따면 이전 코드를 다시 옮겨야 함)
- **`playground/` 밖으로 나가지 않기.** 루트 Makefile은 `srcs/*.c srcs/parsing/*.c srcs/output/*.c`만 긁어가므로 여기 있는 건 실제 빌드에 안 잡힙니다
- **norm은 무시.** 25줄/4인자를 지키면서 처음 배우는 수식을 쓰면 두 배로 힘듭니다. norm은 마지막에 한 번에
- **각 단계 끝에 스크린샷.** 나중에 "언제부터 깨졌는지" 찾을 때 제일 빠릅니다
- **눈으로 확인하고 다음으로.** 한꺼번에 짜면 어디가 틀렸는지 못 찾습니다

## 브랜치

```
main
 └── learn/00-mlx-hello
      └── learn/01-2d-pixels
           └── learn/02-color
                └── ... 계속 파생 ...
                     └── learn/10-interaction

main
 └── feature/render-pixel   ← 학습 끝나고 새로 딴다 (제출용)
```

학습 브랜치는 PR 안 합니다. 다 끝나고 기록용으로 한꺼번에 푸시하거나, 그냥 지우면 됩니다.

## 테스트

`tests/`에 단계별 테스트가 있습니다. **합격 기준은 42 과제와 같습니다 — 그 단계에 주어진 파일이 전부 통과하면 그 단계 완료.**

값은 C 코드에 박혀 있지 않습니다. 각 단계는 `tests/cases/<단계>/` 안의 **케이스 파일**(`.rt`를 닮은 텍스트)로 평가하고, 9단계만 예외로 **실제 `scenes/*.rt`** 를 그대로 씁니다. 지금 `scenes/valid`·`scenes/invalid`가 파서에 대해 하는 역할을 모든 단계로 넓힌 구조입니다.

케이스 파일 30개, 검증 138개.

```sh
cd tests && sh run.sh        # 1~9단계 전부
cd tests && sh run.sh 4      # 4단계만
```

- 아직 구현 안 한 단계는 링크가 안 되므로 **SKIP**으로 넘어갑니다
- ASAN이 켜져 있어 버퍼 넘침을 잡습니다
- 실패가 하나라도 있으면 종료 코드 1
- **케이스는 텍스트 파일이라 재컴파일 없이 직접 추가할 수 있습니다.** 직접 만든 케이스를 넣어보는 게 이 구조의 요점입니다
- 도형은 `.rt`와 똑같이 **지름**으로 적습니다 (러너가 `/2`)
- 각 단계의 파일 목록과 **함수 시그니처**는 그 폴더의 `GUIDE.ko.md` "테스트" 절에, 문법·명령 목록·전체 명세는 `tests/SPEC.ko.md`에
- 함수 이름을 바꾸고 싶으면 `tests/test_0N.c` 상단 선언 한 줄만 고치면 됩니다 (케이스 파일은 그대로). **단 `render_pixel`만은 팀 규약이라 고정입니다**

**0단계와 10단계는 자동 테스트가 없습니다** — 창이 뜨는가 / 움직이는가는 눈으로 봐야 하니까요.

**테스트 통과 ≠ 과제 통과.** 계산이 맞다는 것까지만 보장합니다. 그림이 맞게 보이는가, 시각적 얼룩, 성능, norm, 메모리 누수는 따로 확인해야 합니다.

## 계단

| 단계 | 폴더 | 주제 | 기간 |
|---|---|---|---|
| 0 | `00-mlx` | 창 띄우고 점 하나 | 반나절 |
| 1 | `01-mlx` | 이미지 버퍼로 2D 도형 | 하루 |
| 2 | `02-color` | 색 — 정규화와 보간 | 반나절 |
| 3 | `03-ray-background` | 광선의 등장 | 하루 |
| 4 | `04-sphere` | 첫 3D 도형 | 하루 |
| 5 | `05-shading` | 법선과 조명 | 하루~이틀 |
| 6 | `06-shadow` | 그림자 | 반나절 |
| 7 | `07-plane` | 평면 + 도형 리스트 | 2~3시간 |
| 8 | `08-cylinder` | 원기둥 (제일 어려움) | 2~3일 |
| 9 | `09-scene` | 실제 씬 연결 | 1~2일 |
| 10 | `10-interaction` | 이동 (선택) | — |

테스트 현황: **1단계 7개 파일 28/28 통과.** 나머지는 미구현이라 SKIP.

각 폴더의 `GUIDE.ko.md`에 그 단계에서 **배울 개념 / 쓸 수식 / 구현 순서 / 함정 / 통과 기준**이 적혀 있습니다.

## 분기점

- **7단계 — 구가 평면 위에 그림자를 드리우는 순간.** 여기까지 오면 3~7단계가 전부 맞았다는 뜻이고, 나머지는 도형 추가일 뿐입니다. 심리적으로 제일 큰 고비
- **8단계 원기둥과 9단계 카메라 기저**가 수학적으로 제일 어렵습니다. 나머지는 고등학교 수준
