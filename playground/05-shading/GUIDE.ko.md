## 0. 왜 이걸 하는가

4단계 결과는 빨간 원판입니다. 3D처럼 보이지 않죠. 입체감은 **표면이 빛을 향한 정도에 따라 밝기가 달라지는 것**에서 나옵니다. 그 "향한 정도"를 재는 도구가 **법선(normal)**과 **내적(dot)**입니다.

이 단계는 **세 개의 작은 단계로 쪼개서** 진행합니다. 한꺼번에 하면 어디가 틀렸는지 절대 못 찾습니다.

---

## 1. 배울 개념

### (1) 법선

표면에 **수직인 단위벡터**. 구는 아주 쉽습니다:

```
normal = (P - C) / r          /* 또는 normalize(P - C) */
```

중심에서 표면점으로 향하는 방향이 곧 그 점의 법선입니다.

### (2) 램버트 코사인 법칙

```
밝기 ∝ cos θ = dot(normal, light_dir)
```

- 표면이 광원을 **정면으로** 보면 (θ=0) → cos=1 → 최대 밝기
- **비스듬히** 보면 → cos이 작아짐 → 어두워짐
- **등지고** 있으면 (θ>90°) → cos이 **음수** → 빛이 안 닿음 → **0으로 클램프**

`light_dir`은 **표면점에서 광원으로 향하는 방향**입니다. 반대로 잡으면 밝은 곳과 어두운 곳이 뒤집힙니다.

### (3) ambient (환경광)

빛을 직접 못 받는 면도 완전히 검지는 않습니다. 현실에서는 빛이 여기저기 튕겨서 도달하니까요. miniRT는 그걸 **상수 하나로 근사**합니다:

```
ambient = 물체색 × ambient색 × ambient비율
```

`.rt`의 `A 0.2 255,255,255`가 이 비율과 색입니다.

### (4) diffuse (난반사)

```
diffuse = 물체색 × 광원색 × 밝기 × max(0, dot(n, light_dir))
```

### (5) 최종 색

```
color = ambient + diffuse
```

그리고 **클램프**. 여러 항을 더하니 1을 넘을 수 있습니다.

> specular(반짝이는 하이라이트)는 mandatory 범위 밖입니다. 넣지 마세요.

### (6) 법선 뒤집기

광선이 도형 **안쪽**에서 표면에 닿으면 법선이 광선과 같은 방향을 가리킵니다. 그러면 조명 계산이 뒤집힙니다.

```
if (dot(ray.direction, normal) > 0)
    normal = -normal;
```

## 2. 구현 순서 — 반드시 이 순서로

### (a) 무지개 구 — 절대 건너뛰지 마세요

법선을 **그대로 색으로** 찍습니다:

```
color = (normal + 1) * 0.5      /* -1~1 을 0~1 로 */
```

구가 **부드러운 무지개색 공**으로 보여야 합니다.

- 왼쪽이 빨강(-x/+x), 위가 초록(+y), 카메라 쪽이 파랑(+z) 계열
- **색이 뚝뚝 끊기거나 이상하면 법선이 틀린 것**입니다. 여기서 잡으세요

이 시각화가 **이 단계에서 제일 중요한 도구**입니다. 조명은 여러 항이 곱해져서 틀려도 "좀 어둡네" 정도로 보이지만, 법선 시각화는 틀리면 바로 눈에 띕니다.

### (b) ambient만

조명 없이 `물체색 × ambient색 × 비율`만. 구가 **균일하게 어두운 색**으로 보입니다. 밋밋한 게 정상입니다.

### (c) diffuse 추가

광원 위치를 하드코딩하고 diffuse를 더합니다. **이제 공처럼 보입니다.** 광원 위치를 이리저리 옮겨가며 밝은 부분이 따라 움직이는지 확인하세요.

---

## 3. 함정

**법선 정규화를 빠뜨리기.** `dot`이 cos이 되려면 **둘 다 단위벡터**여야 합니다. 아니면 밝기가 제멋대로 커집니다.

**`light_dir` 방향을 반대로.** `광원 - 표면점`입니다. `표면점 - 광원`이 아닙니다. 밝기가 정확히 반전됩니다.

**음수 클램프를 빠뜨리기.** 광원 반대편이 "음의 빛"으로 이상하게 밝아지거나, 색이 뒤집힌 채로 나옵니다.

**색을 더해야 할 곳에서 곱하기 (또는 반대).**
- 물체색과 빛색 → **곱** (필터)
- ambient와 diffuse → **합** (두 광원의 기여)

**전부 하얗게 나온다.** 클램프 전에 값이 1을 훌쩍 넘은 것. ambient 비율과 brightness가 둘 다 크면 그렇습니다.

**전부 까맣게 나온다.** `dot`이 계속 음수 → `light_dir` 방향 또는 법선 부호 문제.

```sh
cd ../tests && sh run.sh 5
```

**주어진 케이스 파일** — `../tests/cases/05-shading/` 안의 3개. **이 파일들이 전부 통과하면 이 단계 완료**입니다.

- `01_normal.case`
- `02_diffuse.case`
- `03_ambient.case`

케이스는 `.rt`를 닮은 텍스트 파일이라 **재컴파일 없이 직접 추가할 수 있습니다.** 도형은 `.rt`와 똑같이 지름으로 적습니다. 문법과 명령 목록은 `../tests/SPEC.ko.md`.

**요구하는 함수**:

```c
t_vec3	sphere_normal(t_vec3 center, double radius, t_vec3 p);
double	diffuse_factor(t_vec3 normal, t_vec3 light_dir);   /* max(0, dot) */
t_color	apply_ambient(t_color obj, t_color amb, double ratio);
```

**검사 10개**:

| 검사 | 입력 | 기대 |
|---|---|---|
| 법선 | 중심 `(0,0,-5)` r=1, p=`(0,0,-4)` | `(0,0,1)` |
| 법선 단위 | 임의 | 길이 1 |
| diffuse 정면 | `n=(0,1,0)`, `l=(0,1,0)` | 1.0 |
| diffuse 수직 | `l=(1,0,0)` | 0.0 |
| **diffuse 등짐** | `l=(0,-1,0)` | **0.0** (클램프 없으면 -1) |
| diffuse 45° | `l=(0,.707,.707)` | 0.7071 |
| ambient | 빨강 × 흰빛 × 0.2 | `(0.2,0,0)` |
| **색은 곱** | 빨강 × 파란빛 × 1.0 | **검정** (더하기면 실패) |

> 무지개 구 시각화는 자동 테스트로 못 잡습니다. **눈으로** 확인하세요.
