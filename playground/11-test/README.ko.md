# 11단계 — 웹 예시 씬으로 검사

**브랜치**: `learn/11-test` (`learn/10-interaction`에서 파생)

9단계 인수 테스트는 저장소의 씬 15개만 봅니다. 여기서는 GitHub에 공개된 42 miniRT 리포 15곳의 `.rt` 279개와 직접 만든 확인용·경계 씬을 **진짜 파서 + 10단계 렌더러**에 한꺼번에 넣어봅니다.

```sh
sh run.sh              # 전부 (leaks, 시간 측정 포함 - 4분쯤)
sh run.sh --no-leaks --no-time   # 빠르게 (15초쯤)
```

결과는 `out/summary.txt`, `out/results.tsv`(씬마다 한 줄), `out/sheets/sheet_NN.png`(썸네일, 번호는 `index.txt`).

### 고친 것 — 렌더러

**광원이 평면 위에 딱 놓이면 구에 검은 점무늬** (`fix(10)` 커밋). 그림자 광선이 광원 위치에서 평면을 `t = dist − 7e-15`로 맞아 그늘로 판정됐습니다. subject 예시 `L -40,0,30` / `pl 0,0,0 0,1,0`이 정확히 이 배치입니다. `in_shadow`의 `t_max`를 `dist - T_MIN`으로 바꿔 157장 중 해당 3장만 달라졌습니다. **06~09 폴더에는 같은 코드가 남아 있습니다.**

### 팀 파서에 전달할 것 — 받으면 안 되는 입력을 받음 (경계 씬 9개)

| 씬 | 입력 | 지금 |
|---|---|---|
| `trailing_comma` `leading_comma` `double_comma` | `0,0,20,` `,0,0,20` `0,,0,20` | `ft_split`이 빈 칸을 건너뛰어 3개로 읽음 |
| `lone_dot` | `A . 255,255,255` | `str_to_double(".")`이 ok=1, 0.0 |
| `negative_zero_color` `plus_color` | `255,-0,0` `+255,0,0` | 부호 허용, `-0.0 < 0.0`이 거짓 |
| `light_overflow_inf` | 400자리 숫자 | `inf`를 받음 → 광원 방향이 NaN → **화면에 NaN 10,340픽셀** |
| `camera_overflow_inf` `diameter_overflow_inf` | 〃 | `inf`를 받음 (그림은 하늘만) |

`1e1` 같은 지수 표기, 대문자 `SP`, 주석 `#`, 탭 구분은 거부합니다. subject가 딱 정하지 않은 부분이라 불일치로 세지 않았습니다.

### 알아둘 것

- **`scenes/valid/example.rt`는 도형이 한 픽셀도 안 보입니다.** 카메라와 광원이 평면 `y=0` 위에 있고 구·원기둥은 카메라 정확히 옆(90°)입니다. `multi_objects`·`crlf`·`no_trailing_newline`도 같고, 9단계 테스트는 하늘 그라디언트가 단색이 아니라서 통과합니다. 렌더러가 틀려도 이 네 씬은 통과한다는 뜻입니다.
- 도형 수에 비례해 느려집니다 (가속 구조 없음). 10단계 미리보기도 도형 수백 개 씬에서는 버벅입니다.
- `cylinder_paper_thin`(높이 1e-6)이 안 보이는 건 정상입니다. 카메라가 두께 안에서 옆면을 보고 있습니다.

## 이 테스트가 못 잡는 것

그림이 "맞게" 보이는지는 썸네일을 눈으로 봐야 합니다. 창을 띄운 상태(키 입력, 창 닫기)는 자동 검사가 없습니다. norm은 검사하지 않습니다.
