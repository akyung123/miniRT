## 0. 왜 어려운가

구와 평면은 대칭이 좋아서 식이 바로 떨어집니다. 원기둥은 셋이 겹칩니다:

1. **축이 임의 방향** — y축에 정렬돼 있지 않습니다
2. **높이가 유한** — 무한 원기둥을 구한 뒤 **잘라내야** 합니다
3. **뚜껑(캡)** — 측면과 완전히 다른 계산이 두 개 더 붙습니다

그래서 **절대 한꺼번에 짜면 안 됩니다.** (a) 무한 → (b) 유한 → (c) 캡 순서로, 각각 화면을 보고 넘어가세요. 한 번에 짜면 어디가 틀렸는지 찾는 데 며칠 걸립니다.

**먼저 확인할 것**: 캡이 필수인지 subject PDF에서 확인하세요 (리포에 없으니 로컬 PDF로). 필수가 아니면 (c)를 건너뛸 수 있습니다.

---

## 1. 핵심 아이디어 — 축 성분 분해

이 한 줄이 원기둥의 전부입니다:

```
v_perp = v - dot(v, axis) * axis
```

`dot(v, axis) * axis`는 **v를 축 방향으로 투영한 성분**입니다. 그걸 빼면 **축에 수직인 성분만** 남습니다.

원기둥 표면의 조건은 "**축으로부터의 수직 거리 = r**"입니다. 즉 축 성분을 걷어내면 **2D 원 문제와 완전히 같아집니다.** 구에서 쓴 2차방정식이 그대로 재등장합니다.

이 분해를 이해하면 나머지는 계산일 뿐입니다. **여기서 시간을 쓰세요.**

---

## 2. (a) 무한 원기둥 측면

`C` = 축 위의 한 점, `a` = 축 방향(단위벡터), `r` = 반지름.

```
oc = A - C
d_perp  = dir - dot(dir, a) * a
oc_perp = oc  - dot(oc,  a) * a
```

그러면 구와 똑같은 형태:

```
A_ = dot(d_perp, d_perp)
B_ = 2 * dot(d_perp, oc_perp)
C_ = dot(oc_perp, oc_perp) - r²
```

판별식 → 근 → 가장 작은 양수 t. **구에서 한 것과 완전히 동일**합니다.

> `A_`가 0에 가까우면 광선이 축과 평행합니다. 측면과는 절대 안 만나고, 캡만 가능합니다.

**여기까지 하고 화면을 보세요.** 위아래로 무한히 뻗은 기둥이 보여야 합니다.

### 측면의 법선

교차점 `P`에서:

```
m = dot(P - C, a)                  /* 축 위로의 투영 길이 */
normal = normalize(P - C - m * a)  /* 축에서 P로 향하는 수직 방향 */
```

축에서 바깥으로 뻗는 방향입니다.

---

## 3. (b) 높이로 자르기

`m`이 높이 범위 안인지 봅니다. `C`가 원기둥 **중심**이면:

```
-h/2 ≤ m ≤ +h/2
```

범위 밖이면 **그 근은 버리고 다른 근을 검사**합니다. 두 근 다 밖이면 측면 미교차.

> **`C`가 중심인지 밑면인지 헷갈리지 마세요.** miniRT의 `.rt`에서 `cy`의 첫 값은 **중심**입니다. 밑면 기준으로 짜면 원기둥이 절반만큼 어긋난 위치에 나타납니다.

**여기까지 하고 화면을 보세요.** 잘린 기둥이 보이고, **위아래가 뻥 뚫려 있어야** 정상입니다. 안이 들여다보입니다.

---

## 4. (c) 캡 (뚜껑)

캡은 **평면 교차 + 반지름 검사**입니다. 7단계 코드를 재사용합니다.

```
윗면 중심: C + a * (h/2),   법선:  a
아랫면 중심: C - a * (h/2), 법선: -a
```

각 캡에 대해:

1. 평면 교차로 `t` 구하기 (7단계 공식)
2. 교차점이 **중심에서 r 이내**인지: `length(P - cap_center) ≤ r`
3. 맞으면 후보

측면 결과와 캡 결과 중 **가장 작은 t**를 최종 답으로.

캡의 법선은 축 방향(위 캡은 `+a`, 아래는 `-a`)입니다.

## 6. 함정

**축을 정규화 안 함.** 투영 공식 `dot(v,a)*a`는 `a`가 단위벡터일 때만 맞습니다. 파서는 정규화해서 주지만(`valid_direction`), 이 단계에서 하드코딩한 축은 직접 정규화해야 합니다. **이게 1순위 원인**입니다.

**지름/반지름.** `.rt`는 지름을 줍니다. `/2`.

**중심 vs 밑면.** 위 참고.

**두 근 중 하나만 검사.** 작은 근이 높이 밖이라도 **큰 근은 안에 들어올 수 있습니다.** 하나만 보고 버리면 기둥의 일부가 사라집니다.

**법선 정규화 누락** → 조명이 이상해집니다. 무지개 시각화로 확인하세요.

**캡 경계의 이음매.** 측면과 캡 사이에 미세한 틈이나 겹침이 보일 수 있습니다. `≤` / `<` 경계 처리 문제입니다.

**축과 평행한 광선** → `A_ ≈ 0` → 0으로 나눔. `fabs(A_) < 1e-6` 검사.

## 7. 디버깅 도구

막히면 **법선 시각화**(`(n+1)*0.5`)로 돌아가세요. 조명을 끄고 법선만 보면:

- 측면이 매끄러운 색 변화 → 측면 OK
- 캡이 단일 색 → 캡 법선 OK
- 이음매에 이상한 색 → 경계 처리 문제

색이 이상한 곳이 곧 틀린 곳입니다. **조명 켜놓고 디버깅하지 마세요.** 여러 항이 곱해져서 원인이 안 보입니다.
